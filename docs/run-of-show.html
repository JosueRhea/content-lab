Self-hosted Supabase, by hand then as code

Build it manually on EC2 and hit three real failures. Then rebuild it in Terraform, where each one becomes structurally impossible. The Terraform half only lands if they watched you suffer first.

00:00 Runtime 50 min · 2 scheduled waits

Before you go live

Part 1 · Manual 25 min · the pain

0:00
Frame it: “Managed Supabase is $25 a month. What are you actually paying for?”
Promises the payoff. Everything after this is the answer.
0:02
Launch EC2 in the console — t3.medium, 30 GB gp3, inbound :8000
Say why micro fails out loud: thirteen containers will OOM. That limit is the product managed Supabase sells.
0:05
Get a shell with aws ssm start-session, then ./00-preflight.sh
No SSH key, no bastion, no open port 22 — reliably surprises half the room. Preflight then fails fast on RAM, disk and egress, before you have spent a minute on anything.
0:07
./10-install-docker.sh, then ./20-fetch-supabase.sh
Two steps, not one. Each prints the next, and a failure costs you one step instead of the whole build.
0:09
./40-configure-env.sh <IP>, then ./50-up.sh
40 mints the JWTs and patches .env by key. 50 pulls, starts, and blocks until Kong actually answers — so “READY” means ready, not “containers created”.
0:11
Wait 5 minImage pull
Don't fight it — this is the architecture segment. Diagram below.
0:16
PayoffStudio loads. Drop the URL in chat.
First real moment. Let them poke at it while you talk.
0:18
Trap 1JWT mismatch — Studio loads, every API call 401s
The reveal: anon and service_role aren't random strings, they're HS256 JWTs signed with JWT_SECRET. Paste one into jwt.io on screen — payload readable, signature is what fails.
0:21
Trap 2localhost in the public URLs
SUPABASE_PUBLIC_URL is consumed by the browser, not the server — so localhost resolves to the viewer's own laptop. Best taught by having chat confirm it breaks for them too.
0:23
Trap 3Hand-edit the database, then terminate the instance
The table, the data, the .env, the keys — all gone. Nothing you did was written down anywhere. Hand off: “what if the machine were code?”

Filler for the two waits

Wait 1 · image pull · 5 min

The thirteen containers. Kong is the only front door. GoTrue does auth. PostgREST turns tables into a REST API. Realtime tails the write-ahead log. Storage fronts S3-compatible objects. Studio is just a client of all of them.

Land the point: managed Supabase runs this same stack, per tenant. You're not looking at a toy version.

Wait 2 · cloud-init · 6 min

Tail /var/log/supabase-boot.log and narrate what scrolls past.

Good moment for the detour: Terraform has no HMAC function, so the anon and service_role JWTs can't be signed in HCL. They're derived at boot instead — which means those keys never touch your laptop or your shell history.

Cost — two t3.medium at ~$0.083/hr combined, 50 GB gp3 at ~$0.005/hr, Elastic IP free while attached, Secrets Manager $0.40/mo prorated. A two-hour session with rehearsal lands under $1. It bills whether or not you're watching, so run the teardown live.
